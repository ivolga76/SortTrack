## 1. Гарантии безопасности

- Установленное приложение не запускалось.
- Пользовательская SQLite-база не открывалась и не мигрировалась.
- Пользовательские MP3/FLAC не читались и не изменялись.
- Все пути fixture начинаются с несуществующих `X:\SortTrackFixture` или `X:\SortTrackBenchmark`.
- Нагрузочный скрипт требует явный `--output`, не перезаписывает файлы и отказывается создавать базу внутри `%LOCALAPPDATA%\SortTrack`.
- Синтетическая база хранится в `work/r0` и исключена из source control.

## 5. Предварительный query baseline

30 повторений после одного прогрева:

| Сценарий | p50 | p95 | max |
|---|---:|---:|---:|
| Первая страница библиотеки, 100 строк | 110,801 мс | 117,065 мс | 117,370 мс |
| Глубокая Offset-страница 99 900 | 134,767 мс | 143,743 мс | 151,579 мс |
| FTS конкретного трека | 0,045 мс | 0,124 мс | 0,135 мс |
| Combined filter count | 39,539 мс | 44,866 мс | 45,833 мс |
| SQL-чтение плейлиста из 10 000 items | 5,321 мс | 6,078 мс | 7,626 мс |

Ограничения измерения:

- измеряется SQLite query, а не полный Tauri IPC + React render;
- файлы синтетические и физически отсутствуют;
- playlist test не измеряет сериализацию 10 000 полных Track DTO;
- cold disk и антивирусное сканирование отдельно не измерены.

Выводы:

- текущие Library queries укладываются в предварительный бюджет 300 мс на синтетической базе;
- FTS не является текущим узким местом для специфического запроса;
- пагинация плейлистов всё равно обязательна, потому что проблема находится в полном DTO/IPC/DOM, а не в простом SQL select;
- keyset pagination пока не нужна немедленно, но остаётся предметом сравнения на R4.

```text
npm test -- --run
npm run build
npm run typecheck
npm run ipc:check
cargo test --manifest-path src-tauri/Cargo.toml
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings
npm run benchmark:generate -- --output work/r0/benchmark-v13-100k.db --tracks 100000 --playlists 1000 --large-playlist-items 10000
npm run benchmark:queries -- --database work/r0/benchmark-v13-100k.db --iterations 30
```

Генератор не перезаписывает существующую базу. Для повторного запуска нужно выбрать другой путь либо вручную удалить только ранее созданный синтетический артефакт после проверки его manifest.

## 7. Rollback перед R1

1. Не использовать реальный installed/portable профиль для разработки модулей.
2. До первой миграции новой версии создать штатный backup и отдельную файловую копию тестового профиля.
3. Каждый structural commit должен проходить текущий regression suite.
4. Старые gateway/repository facades удаляются только после переключения всех потребителей и прохождения characterization tests.
5. При несовпадении counts, integrity, foreign keys или IPC snapshot этап останавливается; миграция или новая граница не принимается.
