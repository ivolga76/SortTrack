# Протокол приёмки SortTrack MVP 1.0

**Статус:** выполняется  
**Первый локальный release candidate:** 0.1.0, сборка 17 августа 2026 года  
**Область:** Windows 10/11 x64, installed и portable, MP3/FLAC  
**Главный принцип:** любые проверки записи и аварийного завершения выполняются только на тестовых копиях файлов и базы.

## 1. Правила статусов

- `PASS` — проверка выполнена, результат и доказательство зафиксированы.
- `FAIL` — результат не соответствует ожидаемому; создан дефект.
- `BLOCKED` — отсутствуют данные, программа или разрешение для проверки.
- `N/A` — неприменимо только с письменным объяснением.

Публикация запрещена, пока есть хотя бы один `FAIL` или `BLOCKED` по критериям `MVP-01`–`MVP-21`, открытый дефект P0/P1 либо неподтверждённая целостность исходных файлов.

## 4. Безопасность тестовых данных

Перед ручной проверкой необходимо:

1. Создать отдельную тестовую папку, не являющуюся единственным местом хранения музыки.
2. Сохранить SHA-256 manifest исходного состояния тестовых MP3/FLAC.
3. Создать отдельные папки `source`, `copy-destination`, `exports` и `backups`.
4. Убедиться, что installed и portable используют разные тестовые профили.
5. Все проверки записи тегов выполнять на специальных копиях; после проверки сравнивать аудиодекодирование и ожидаемые теги.
6. Все проверки нехватки места, отзыва доступа и принудительного завершения проводить только после успешного обычного прогона.
7. Не запускать fault injection на пользовательской библиотеке или единственной копии базы.

Рекомендуемый состав корпуса описан в `MVP_TEST_CORPUS.md`.
