## Цель проекта

SortTrack — бесплатное публичное desktop-приложение с открытым исходным кодом под AGPL-3.0 для одного пользователя на одном Windows-компьютере. Основной сценарий: безопасно разобрать новую локальную коллекцию MP3/FLAC объёмом 50 000–100 000 треков по жанрам и папкам.

Главный приоритет: максимальная надёжность любых операций с файлами. Приложение local-first; логи, база, результаты анализа и модели остаются на компьютере пользователя. Установочная папка: `%LOCALAPPDATA%\SortTrack`.

Полное техническое задание находится в `TZ.md`.

## Зафиксированные продуктовые решения

- Поддерживаются только MP3 и FLAC.
- Исходные файлы находятся на внутреннем диске.
- Копирование достаточно; автоматическое перемещение не требуется.
- Файлы никогда не перезаписываются автоматически.
- Конфликты показываются списком; решение можно применить ко всем конфликтам одного типа.
- Редактирование метаданных записывает изменения непосредственно в MP3/FLAC, но только через preview, отдельную копию, повторное чтение и атомарную замену.
- Для каждого трека хранится полная история подтверждённых изменений.
- Точный дубликат определяется по полному SHA-256. Программа только показывает рекомендации и предпочитает целостный FLAC с более полными тегами.
- Плейлисты экспортируются в UTF-8 M3U8 и отдельный Traktor NML; `collection.nml` не изменяется.
- Жанровая модель выдаёт три кандидата. Никакой автоматический или ML-жанр не записывается в файл без отдельного подтверждения пользователя.
- Score не называется вероятностью без калибровки.
- Выпуск аудиомодели допускается только при top-1 accuracy не ниже 70% на test, наличии не менее 1000 записей, всех восьми широких жанров и отсутствии ошибок извлечения признаков.

## Текущая архитектура

- Tauri 2 desktop shell.
- Rust backend.
- React 19 + TypeScript + Vite frontend.
- SQLite с последовательными миграциями.
- База приложения: `%LOCALAPPDATA%\SortTrack\database\sorttrack.db` через Tauri `app_local_data_dir`.
- Symphonia 0.6 декодирует MP3/FLAC локально.
- RustFFT 6.4.1 рассчитывает FFT для аудиопризнаков.
- Lofty читает и записывает теги.
- Все длительные вычисления запускаются через blocking runtime, чтобы не блокировать UI.

## Реализованные функции

### Библиотека и проигрыватель

- Безопасное рекурсивное сканирование MP3/FLAC без перехода по symlink.
- Реальные теги, длительность, bitrate, sample rate, bit depth и channels.
- Изоляция повреждённых файлов без остановки общего сканирования.
- Поиск, фильтрация и локальный проигрыватель.
- Waveform с перемоткой кликом.
- Контролируемый временный доступ WebView только к выбранному файлу.

### Плейлисты и файлы

- Несколько одновременно открытых ручных плейлистов.
- Создание, переименование, изменение порядка и drag-and-drop между плейлистами.
- Безопасное копирование через временный файл с проверкой размера и SHA-256.
- Preview конфликтов, действия `skip` и безопасное новое имя.
- Постоянный журнал Copy и восстановление после аварийного завершения.
- Безопасная отмена удаляет только строго принадлежащий операции временный файл.
- Экспорт M3U8 и Traktor NML 19 для Traktor Pro 3/4.

### Дубликаты и метаданные

- Точные дубликаты по полному SHA-256.
- Проверяемый hash-cache по размеру, времени изменения и физической идентичности файла.
- Рекомендация предпочтительного экземпляра без удаления.
- Одиночное и массовое редактирование до 1000 файлов.
- Обязательный preview и изоляция ошибки каждого отдельного файла.
- Запись тегов в копию, повторное чтение, проверка и атомарная замена.
- История метаданных и защита от внешнего изменения между preview и commit.

### BPM и музыкальная тональность

- Реальный локальный DSP-анализ MP3/FLAC.
- BPM, key и Camelot notation.
- Максимум 240 секунд аудио на трек.
- Постоянная очередь до 1000 треков с прогрессом по файлам/байтам, паузой, отменой и восстановлением после перезапуска.
- Результаты, score, версия алгоритма и снимок файла хранятся отдельно от тегов.
- Алгоритм: `sorttrack-dsp-1`.
- Кэш сбрасывается при изменении исходного файла или метаданных.

### Жанровый помощник

- Всегда показывает top-3 кандидата.
- Первый объяснимый слой использует genre tag, aliases, папку, filename и BPM.
- Версия: `metadata-path-bpm-1`, taxonomy version 1.
- Для каждого кандидата сохраняются score и список использованных сигналов.
- Ручное подтверждение, ручной выбор другого жанра, история решений.
- Фиксация жанра защищена на уровне Rust backend; изменить зафиксированный жанр обходным вызовом нельзя.
- Есть отдельное действие снятия фиксации.
- Подтверждение не записывает genre tag в аудиофайл автоматически.

### Validation dataset

- Аудит только зафиксированных ручных labels.
- Целевой объём: 1000 доступных треков.
- Показываются баланс широких жанров, отсутствующие классы и предупреждения.
- JSON manifest создаётся атомарно, без копирования аудио и без перезаписи существующего файла.
- Перед экспортом проверяются снимки файлов и рассчитывается/повторно используется SHA-256.
- Записи группируются консервативно по нормализованным `artist + title`, с SHA-256 fallback.
- Одна группа записи попадает только в один split.
- Детерминированное разбиение: 70% train, 15% calibration, 15% test.
- Конфликтующие labels одной группы исключаются и отражаются в отчёте.
- История экспортов и SHA-256 manifest сохраняются в SQLite.

Ограничение: до внедрения acoustic fingerprint одинаковые записи MP3 и FLAC связываются по `artist + title`. В отчёте это явно указано; спорные ремиксы и версии нужно проверять вручную.

### Первый аудио-ML baseline

- Extractor version: `sorttrack-audio-features-1`.
- Model version: `nearest-centroid-baseline-1`.
- Из аудио извлекаются 25 признаков.
- Исключается тишина; выбираются до 32 репрезентативных окон.
- Признаки включают RMS, zero-crossing rate, spectral centroid, bandwidth, rolloff, flatness, четыре спектральных диапазона, spectral flux, статистики, BPM и длительность.
- Признаки кэшируются по extractor version, физической идентичности, размеру и времени изменения файла.
- Любое изменение файла или тегов сбрасывает feature-cache.
- Нормализация и центроиды обучаются только на train.
- Calibration используется для масштаба distance score.
- Test используется только для финальной оценки.
- Ошибка извлечения test-файла остаётся в знаменателе accuracy и не может искусственно улучшить результат.
- UI показывает top-1 accuracy, failed features, per-class recall и confusion matrix.
- Модель и метрики каждого запуска сохраняются в SQLite.

Важно: фактическая точность на пользовательской коллекции ещё не измерена. Цифры в browser/demo режиме являются демонстрационными и не являются результатом реальной модели.

## Что делать следующим

1. Установить или запустить текущую production-сборку.
2. Добавить реальную музыкальную библиотеку.
3. Подтвердить и зафиксировать эталонные широкие жанры примерно для 1000 треков, следя за балансом классов.
4. Открыть `ML dataset`, проверить аудит и устранить отсутствующие/малочисленные классы.
5. Создать реальный JSON manifest.
6. Запустить `Оценить baseline`.
7. Зафиксировать реальные accuracy, confusion matrix и per-class recall.
8. Проанализировать основные пары ошибок.
9. Если baseline не достигает критерия, улучшать feature extractor/классификатор, не используя test для подбора.
10. Подключать аудиомодель к top-3 жанрового помощника только после выполнения критерия выпуска.

## Обновление этапа: gated inference и отчёты модели

- Последняя сохранённая оценка модели восстанавливается в окне `ML dataset` после перезапуска приложения.
- Отчёт последнего model run экспортируется в локальный JSON. Запись выполняется через временный файл и атомарное создание назначения без перезаписи существующего файла.
- В отчёт входят версия схемы, идентификатор запуска, версии модели и признаков, SHA-256 manifest, критерий выпуска и полные метрики. Веса модели в отчёт не включаются.
- Жанровый помощник запрашивает аудиопрогноз только у запуска с `meets_release_threshold = 1`.
- Пока одобренного запуска нет, аудиофайл для ML-рекомендации не декодируется, а прежняя логика metadata/path/BPM работает без изменений.
- Одобренная модель добавляет до трёх широких жанров. Её сигнал сильнее пути/имени файла, но слабее точного genre tag; ручное подтверждение и фиксация остаются главными.
- Score аудиомодели отображается как оценка, а не вероятность. Автоматическая запись жанра в MP3/FLAC не выполняется.
- Реальная пользовательская модель пока не оценивалась и не активирована. Демонстрационные цифры интерфейса не являются результатом обучения.

## Обновление этапа: безопасное восстановление backup

- Восстановление начинается с read-only preview: проверяются формат manifest, SHA-256 и размер базы, `PRAGMA integrity_check`, версия схемы и фактические счётчики содержимого.
- Backup с более новой схемой отклоняется; старая поддерживаемая схема будет мигрирована штатным механизмом после восстановления.
- Между preview и подтверждением повторно проверяется SHA-256 manifest. Изменившийся backup отклоняется.
- Для подтверждения пользователь должен вручную ввести `ВОССТАНОВИТЬ`.
- Перед staging выполняется checkpoint WAL и создаётся отдельный постоянный safety backup текущей базы.
- Восстановленная база копируется в уникальный staging-файл рядом с активной БД, синхронизируется с диском и повторно проходит SHA-256 и integrity check.
- Pending restore публикуется атомарно, после чего Tauri запрашивает штатный перезапуск приложения.
- Переключение выполняется до открытия SQLite: активная база переименовывается в rollback, staging становится активной базой и ещё раз проверяется.
- При ошибке переключения старая база возвращается. Операция умеет продолжиться после сбоя между двумя переименованиями.
- Старые `-wal`/`-shm` перемещаются вместе с rollback и не могут быть применены к восстановленной базе.
- После успеха временный rollback удаляется, а постоянный safety backup сохраняется.
- Добавлены fault-path тесты восстановления после прерывания и отклонения backup, изменившегося после preview.
- Актуальные проверки: 43 Rust-теста и 19 frontend-тестов. Production build и NSIS packaging прошли; запуск именно этой сборки не выполнялся, поскольку автоматическая проверка не получила разрешение на возможное применение заранее подготовленного pending restore к локальной базе.

## Обновление этапа: надёжное повторное сканирование

- После успешного обхода зарегистрированной папки SortTrack сверяет сохранённые пути с файловой системой через `try_exists`.
- Исчезнувший файл получает `availability_status = missing`; запись трека, метаданные, история, результаты анализа и ссылки из плейлистов не удаляются.
- Перед записью `missing` существование пути проверяется повторно внутри операции, что уменьшает риск гонки с внешним перемещением файла.
- Ошибка проверки доступа не превращается в `missing`: она попадает в отчёт сканирования, а прежний статус сохраняется.
- Вернувшийся по прежнему пути файл выводится из `missing`, даже если размер, mtime и file identity не изменились.
- Перемещение внутри одной библиотечной папки распознаётся по стабильной физической идентичности файла. Если старый путь действительно исчез и найден ровно один кандидат, обновляется существующая запись вместо создания нового трека.
- Простое копирование не считается перемещением, пока исходный путь существует.
- Отчёт scan отдельно показывает `moved`, `restored` и `missing`.
- В таблице отсутствующий трек приглушён и подписан `Файл отсутствует · запись сохранена`; двойной клик не запускает playback.
- Интеграционный тест покрывает первоначальный scan, повторный scan, переименование, исчезновение и возвращение файла без появления дублирующей записи.

## Обновление этапа: рейтинг в библиотеке

- Под названием каждого трека отображаются пять интерактивных звёзд. Нажатие устанавливает оценку 1–5, повторное нажатие выбранной звезды сбрасывает её в 0.
- Интерфейс блокирует звёзды только изменяемого трека, сохраняет выбранный и проигрываемый объекты согласованными, затем перечитывает текущую страницу и все плейлисты.
- Backend принимает идентификатор трека, ожидаемый старый рейтинг и новое значение. Значения вне 0–5, отсутствующий трек и устаревшее ожидаемое состояние отклоняются.
- Обновление рейтинга и добавление истории выполняются одной SQLite-транзакцией. Операция без фактического изменения не создаёт лишнюю запись истории.
- Миграция v13 добавляет `track_rating_history` с предыдущим и новым значением, источником и временем. История остаётся только на компьютере и входит в обычный SQLite backup.
- MP3/FLAC и их теги при выставлении рейтинга не изменяются. Рейтинг является организационным полем SortTrack.
- Добавлен repository-тест успешного изменения, единственной записи истории, безопасного no-op, отклонения устаревшего значения и диапазона вне 0–5. Актуально: 70 Rust-тестов и 29 frontend/DevOps-тестов; Clippy и production frontend build проходят.

## Обновление этапа: история и массовый рейтинг

- В боковой истории окна метаданных появился отдельный раздел последних 100 изменений рейтинга с датой, предыдущим и новым значением.
- В панели выбранных треков добавлены выбор оценки `1–5`, сброс в `0` и отдельное применение. Массовая команда принимает от 1 до 1000 идентификаторов.
- Backend удаляет повторяющиеся идентификаторы, валидирует целевой рейтинг и обрабатывает каждый уникальный трек независимо: `saved`, `unchanged` или `failed`.
- Все успешные изменения одной массовой команды и соответствующая история фиксируются одной SQLite-транзакцией с источником `bulk`. Отсутствующий трек не мешает обработать остальные.
- После операции интерфейс перечитывает текущую страницу и плейлисты, а также синхронизирует выбранный и проигрываемый трек. Пользователь получает итог по сохранённым, неизменившимся и ошибочным записям.
- Массовая оценка не записывает теги и не изменяет MP3/FLAC. Схема остаётся v13, так как таблица истории создана на предыдущем этапе.
- Repository-тест расширен проверкой дедупликации, частичного результата, записи источника `bulk` и корректных счётчиков. Актуально: 70 Rust-тестов и 29 frontend/DevOps-тестов; Clippy и production frontend build проходят.

## Обновление этапа: расширенные фильтры библиотеки

- В сворачиваемую панель добавлены нижняя и верхняя границы BPM, минимальный рейтинг, Camelot, формат MP3/FLAC и состояние файла: доступен, повреждён/не читается или отсутствует.
- Все заполненные условия объединяются через `AND` вместе с полнотекстовым поиском, широким жанром и режимом входящих. Активные условия считаются на кнопке панели и сбрасываются одной командой.
- Backend независимо проверяет конечность и диапазон BPM 0–400, порядок границ, рейтинг 1–5, канонический Camelot, формат и закрытый список состояний.
- Условия применяются в SQLite до `count`, сортировки, `LIMIT` и `OFFSET`; общее количество и страницы относятся уже к отфильтрованному набору. В WebView не загружается вся коллекция.
- Для одной логической записи по-прежнему выбирается предпочтительный файл; поэтому наличие MP3 и FLAC одной записи не создаёт повторов. Фильтр формата относится к этой предпочтительной копии.
- Команда перехода к проигрываемому треку сбрасывает расширенные фильтры, если они могли скрыть его, и затем открывает вычисленную страницу.
- Пользовательские заметки исключены из объёма MVP по решению владельца; `TZ.md` актуализирован. Резервное поле базы не получает интерфейс или отдельную историю.
- Repository-тест расширен сочетанием BPM, рейтинга, Camelot, MP3 и доступности, отдельным поиском проблемного файла и отклонением перевёрнутого диапазона. Актуально: 70 Rust-тестов и 29 frontend/DevOps-тестов; Clippy и production frontend build проходят.
